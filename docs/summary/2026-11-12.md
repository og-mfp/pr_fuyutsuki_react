Title: Check email OTP for users without MFA

Goals:
Determine whether a user without enrolled MFA receives an email one-time password during login.

Plans:

1. Trace the Fortify password-login action and risk enforcement branch.
2. Compare with the app's email challenge flow and related feature tests.
3. Record the finding and answer without changing application code.

Solution summary:
Confirmed that a user without MFA does not receive an email OTP during login. When global MFA is enabled, Laravel Fortify's two-factor path applies only to users with an enabled authenticator factor. The custom risk step-up flow also does not send email: when enforcement is active and risk is medium/high, unenrolled users are temporarily denied and prompted through the generic login error; a verified password reset can recover access once. When risk mode is monitor, or step-up is off, risk assessment does not block login.

Email OTP is implemented for sensitive account changes in `SecurityChallengeController`, where an email code is issued if the user has no enabled MFA. This is separate from login. Existing `AuthenticationRiskTest` coverage confirms denial and password-reset recovery for unenrolled risky accounts, and Fortify authenticator challenge for enrolled accounts.

| Area               | Result                                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------- |
| Login/MFA behavior | No email OTP sent to unenrolled users during login.                                                                 |
| Risk enforcement   | Risky unenrolled login is denied when enforcement and step-up are enabled; recovery is via verified password reset. |
| Sensitive changes  | Email OTP is sent when an unenrolled user authorizes a protected account change.                                    |

4. Verify tests, frontend checks, and build.

Solution summary:

Server endpoints scope role IDs to the requested group, recheck assignment authority in a transaction, and preserve owner, restricted-permission, and last-administrator safeguards. Updated registration's no-privileged-default-role validation and installation readiness checks. The historical owner-binding migration handles both pre-role installs and role-backed schemas.
